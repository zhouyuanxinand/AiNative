# 前序步骤返回与资料分析操作区

## 用户要求

从需求确认返回资料识别后，将“核对需求”放入资料分析顶部操作区；从后续步骤返回前序步骤时，提示资料修改可能影响后续结果。

## 实施方案

1. 资料分析操作区复用原有按钮行：未采用时为“重新分析资料 / 确认采用”，采用后为“重新分析资料 / 核对需求”。移除对应底部重复按钮，保留忙碌与资料版本限制。
2. 按现有办理步骤顺序识别向前序步骤返回；统一拦截内部导航与浏览器历史导航，使用平台 Ant Design 确认弹窗。取消保留当前 URL、页面、滚动和填写；确认后才更新最近位置。前进、同一步、资料依据/项目流程等辅助查看不重复提示。
3. 提示明确：查看不会改动数据；修改并保存前序资料可能使后续确认与成果需要重新核对。导航本身不调用业务写入，也不删除已有成果。
4. 保持已有表单挂载、未保存草稿及跨项目离开保护。成功业务操作引起的自动继续仍按服务端状态处理。

## 验证范围

- 定点浏览器验证：顶部按钮位置及窄屏换行；前序导航取消/确认/Escape；浏览器后退和前进；草稿保留与无业务写入。
- 运行完整受影响导航/资料分析测试文件及 TypeScript/构建检查，不运行无筛选全量。
- 使用现有真实案例只读核验并截图；不替用户采纳、澄清或修改项目资料。
