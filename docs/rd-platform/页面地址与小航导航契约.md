# 页面地址与小航导航契约

本轮将页面定位与页面筛选分开：路径表达所在对象和办理步骤，查询参数只保留当前页面的非默认筛选。路由唯一由 `web/src/features/rd/platformNavigation.ts` 编解码；目录组件使用 `useDirectoryState`。后端 `navigation.py` 提供可发现的路由目录和授权后的当前上下文。

## 筛选、历史链接与返回

- `/`、`/rd` 和旧 `?rd_view=...&project=...&case=...&step=...`、`/rd/projects/.../cases/...` 链接继续可读；进入后替换成规范路径，不增加一条无效的返回记录。
- 只有当前目录的非默认值进入 URL。例如 `/projects?q=YLZJ`；流程模板固定版本、画布/历史页、运营筛选与台账页也可恢复。`page=1`、`all`、其他页面的筛选不会累积。
- 不在地址中存放草稿、滚动像素、凭证、模型回答或业务记录正文。搜索文字可能包含用户输入，复制地址前仍需注意搜索内容。
- 离开目录时，其他页面的筛选放在当前浏览器历史状态中；同案例表单继续保持挂载。刷新、前进后退和未保存确认沿用原工作面规则。
- 显式步骤链接优先于继续位置；尚不具备办理条件时仍由业务工作面判定可达范围。打开链接不会采用资料、批准需求或启动生成。
- OA 回跳先由服务端校验并清理凭证，再由前端规范化路径。部署端口不是页面身份的一部分。

## 小航的页面引用

长期保存位置时使用结构化引用，不保存整条浏览器地址：

```json
{
  "schema_version": 1,
  "route_id": "case.requirements",
  "project_id": "project-123",
  "case_id": "case-456"
}
```

引用仅表示“到哪里”。不能从该引用推断需求已确认、流程已完成或用户有访问权限。对象 ID 与名称分开，ID 不随项目改名而变化。`workpackage_id` 仅允许在 `case.execution` 中出现。

接入顺序：

1. `GET /api/rd/navigation/catalog`：发现支持的页面 ID、路径模板与只读能力。
2. `POST /api/rd/navigation/context`，请求体为上述引用：服务端检查当前账号可访问的项目、流程、工作包，返回当前项目版本、输入修订、阶段和数量，以及可定位的页面引用。
3. 前端 `locationFromPageReference` + 原导航入口：生成当前部署下的相对地址，继续经过草稿保护和原办理条件。

上下文接口不调用模型、不修改项目、不增加业务版本。不存在或无权访问对象统一拒绝；客户端传来的版本、权限、状态、额外 URL 等字段不被接受。

当前案例助手在提问时附带当前页面引用；返回的定位沿用原工作面导航，并保留具体工作包。重试保留首次请求的页面引用和幂等键。未提供引用的旧请求仍兼容。

## 后续扩展边界

本轮完成的是稳定页面标识、上下文读取、导航与校验的基础。现有会话记录继续使用原存储；尚未新增跨会话事实记忆库，也未赋予小航自动批准或生成的写入权限。将来接入长期记忆时，应同时记录对象引用、读取时版本、来源和时间，再使用上下文接口复核当前事实；业务动作另行定义输入契约、权限、幂等及审计。
