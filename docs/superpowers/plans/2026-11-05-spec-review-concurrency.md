# 规范对照建议：分批并发开发计划

## 目标和边界

需求确认的规范核对已按 15 条分批，但当前逐批等待模型。改为每次核对最多 3 批在途，保持每批完整规范和现有引用校验，减少累计等待。只优化规范建议，不改原文、用户实际结果、任务书生成引擎或采纳规则。

## 实施

1. 先用隔离模型响应验证多批调用重叠、乱序完成、返回行乱序，并保留串行基线计时；不以外部模型随机速度作为测试断言。
2. 规范正文只提取一次。有限线程池滚动派发批次，最多 3 个在途；成功批次全部验证后再提交下一批，任何失败取消尚未开始的任务。按原批次位置、需求 ID 和需求版本汇总，不按响应时间追加。
3. 复用现有线程上下文传播，验证编制模型、OA 统计身份和请求凭证上下文没有丢失。使用统一 240 秒模型预算、每次请求最长 120 秒、最多 2 次传输尝试，排队和重试共享截止时间。
4. 仍由 store 在全部批次成功后统一保存，沿用权限、来源哈希、项目版本检查及幂等回执；错误或版本变化不得部分写入，不改已采用指标或历史结果。
5. 记录批次和总耗时（不记录文档正文、凭证），便于后续排查。界面沿用现有加载与结果渲染协议，不引入假进度。

## 验证与交付

- 新增并发专项测试：69 条分 5 批、最多 3 并发、乱序对齐、身份传播、错误停止后续派发和共享超时。
- 完整运行受影响的规范建议和规范审阅测试文件，复用上一轮其他全量/相关验证；本轮不跑无筛选全量。
- 对已有液冷项目只读快照做真实模型验证，保留响应及计时，不修改用户项目；报告真实耗时，不承诺固定加速倍数。
- 定向审查后，确认本地服务空闲再加载代码，保留配置，不自动提交。
