# 需求确认门槛与返回澄清

## 原因与修复

前端下一步只检查有来源需求和必需澄清，没有检查规范建议的逐条决定。服务端在保存基线之前拒绝确认，因此业务阶段仍是需求阶段，但用户已进入缺少明确返回入口的确认页面。

共享 `requirementConfirmationBlockers` 用当前来源、规范建议批次、逐条决定/澄清采用、旧增强建议及历史、明确采用值判断可确认状态。无建议或 `not_found` 不增加人工决定要求。服务端校验保持原样。

需求工具栏保留原确认按钮，条件不足或有未保存输入/需求/澄清时禁用并给出原因。确认页和服务端拒绝后的弹窗都有“返回需求与澄清”；返回关闭弹窗并保留确认范围，不提交业务回退或自动采纳。范围草稿不会阻止返回后重新进入确认。
