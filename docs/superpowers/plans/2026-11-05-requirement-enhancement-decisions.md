# 需求增强与逐项确认

依据主题方案 01 §17.4.3–17.4.5 及 05 的需求确认验收规则，沿用已发布流程模板及现有任务书引擎。

1. 资料分析保留全部原文行、来源版本和全屏审阅；将有引用依据的增强建议与原文、自有组件能力值分开。无有效依据时不生成推荐值。
2. 需求确认复用原文行与稳定需求 ID，在六列表中进行采纳、不采纳、填写实际结果及办理澄清。保留人工草稿，显式操作才更新业务记录；第一步的单条采纳同样使用该决定逻辑。
3. 实际结果和决定记录关联经校验的建议、输入版本、操作者。过期来源及未闭合的必需项不得静默进入确认，原始指标不随人工决定改写；沿用既有版本、历史与选型门禁。
4. 核验建议来源、逐项写入和确认门禁、前端构建与资料/确认页面的滚动、全屏、草稿、成功和失败路径；不运行无关全量测试。
