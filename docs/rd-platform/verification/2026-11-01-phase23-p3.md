## API 合同

统一前缀 `/api/rd`，写入使用 Idempotency-Key。读取和写入均按 verified actor 验证角色；来源副本还要求项目访问权限。管理列表默认每页 5 项，先授权过滤再分页计数。

- `GET/POST /template-rules`：POST 为 multipart，payload={target:{product_type,domain},operations,reason}，另上传 target_profile / target_mapping；服务器计算字节摘要。
- `POST /template-rules/{id}/review`：{approved,reason,expected_digest}；`/publish`：{expected_digest}。
- `GET/POST /template-derivations`，`GET /template-derivations/{id}`。POST 指定受控 baseline_product_type/domain、target、project_id、case_id、source_ids、rule_id、professional_evidence；不接受任意路径或自报批准。
- `POST /template-derivations/{id}/bind-project`：供旧 onboarding 候选使用，{project_id,case_id,source_ids,expected_input_revision,expected_manifest_digest}。已有固定输入不能改绑。
- `POST .../{id}/regression`：{project_id,case_id,expected_input_revision}；直接调用原引擎，成功才形成可审核证据。
- `POST .../{id}/visual-review`：multipart pages[]、expected_asset_digest、conclusion、reason；需审核者角色，保留实际图片及哈希，并绑定回归收据。
- `POST .../{id}/review`：{approved,reason,expected_manifest_digest}；服务器读取已有证据，不接受布尔值替代回归文件。
- `POST .../{id}/publish`：{expected_target_digest}；`/rollback`：{reason}。
- `GET .../{id}/assets/{relative}`：候选内安全文件解析和项目权限检查；不提供任意文件系统路径。

治理写入采用原子收据日志。已知失败保留尝试并允许同键重试；成功同键返回原回执；异常中断遗留的 started 状态返回 409，要求核对事实，避免盲目重复真实模型或发布副作用。

- 合并运行：补缺循环、模板语义、澄清、执行器、原 engine_contract、派生 HTTP、派生／规则域、onboarding、模板版本 API、规则编辑 API、章节型模板版本，共 **128 项通过**（154.02 秒）。随后最新改动的六文件聚焦回归 **55 项通过**（51.69 秒）；最终新增／变更的四文件专项 **38 项通过**（14.71 秒）。仅有 FastAPI/TestClient 依赖弃用警告；各批不是互相独立的累加测试数。
