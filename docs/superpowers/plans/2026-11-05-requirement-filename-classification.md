# 需求文件名识别补齐计划

用户指定：文件名中的“技术要求”“技术协议”“沟通指导书”“技术规格书”均表示需求文件（tech）。支持前后附产品型号、版本和其他名称。

当前批量选择与拖入统一调用后台文件名分类接口；现有明确规则只包含“技术要求”，另外三类可能被留为待分类或交由模型判断。

1. 补齐后台确定性文件名规则，四类均直接识别为 tech，无需模型调用；同步模型分类提示中的需求类型定义。
2. 保留需求与产品规范名称同时出现时的歧义提示、用户手工调整优先级，以及每类只选一份主文件的原行为。
3. 验证包含型号、版本、不同扩展名的批量文件在启用和禁用模型时都正确归类，且分类接口不修改项目。只执行完整受影响分类测试文件，不运行全量。
4. 加载到当前本地后端，不改任务书生成逻辑，不提交代码。
