# 流程模板目录自动更新开发计划

> 使用 writing-plans 记录本轮已确认范围；在当前工作树执行，沿用 frontend-design / frontend-design-premium 的既有控件与交互合同。

**目标：** 移除新建项目及新增流程弹窗中的“刷新模板目录”，让目录在使用时自动更新，同时保持已经选择的固定模板版本。

**依据：** 用户本轮要求完成上一轮第一条。六项业务参数的展示和编辑不在此次范围。

**实现：** 继续使用 `RdPlatformPage.tsx` 的 `rdCatalog` 请求和取消机制。打开创建弹窗、从流程管理同页返回、创建弹窗打开后重新激活浏览器页面时自动重读。合并 focus/visibility 的重复事件，后台隐藏时不发起。创建中、结果未知和待核对冲突时不改变目录或请求快照。已选择的模板对象随表单保存，目录更新不会换版本；是否可采用仍由服务端校验。

**文件：**
- `web/src/features/rd/RdPlatformPage.tsx`：目录刷新时机、固定选择、移除按钮及失败重试。
- `web/tests/rd-project-workflow-entry.browser.mjs`：扩展既有隔离浏览器用例，保留原有流程及版本断言。
- `UX-CONTRACT.md`：记录目录自动更新行为。

**验证边界：** 只运行完整的受影响浏览器测试文件、TypeScript/Vite 构建及改动差异检查；不执行无筛选全量，不改既有超时，不调用模型，不写入真实项目。

**复查补充：** 返回页面时若旧目录请求尚未完成，取消旧请求并发起最新读取，不得直接忽略本次返回事件。延迟的旧响应不得覆盖新目录，用浏览器延迟响应夹具验证。
