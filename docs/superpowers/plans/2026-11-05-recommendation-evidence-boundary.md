# 需求确认建议与原文证据分离

## 问题与范围

实际案例有 64 条需求、6 条资料识别阶段的旧增强建议，尚无独立规范建议批次。6 条建议均引用需求文件自身，与原始指标引用相同。前端与后端在没有规范批次时回退至这些建议，提前显示采纳操作并阻止需求确认。

## 开发步骤

1. 用隔离案例复现“没有规范批次但出现建议和确认阻断”，保留实际项目数据用于只读核对。
2. 资料识别只提取需求原文与业务参数，不生成可采纳的增强建议。忽略模型越界返回的建议；原始指标、引用与定位保持完整。
3. 需求确认表只展示独立规范对照批次的建议及证据。原始需求出处仍在“查看原文”显示。没有规范批次时显示“尚未核对规范”，不能采纳资料识别阶段的旧建议。
4. 服务端审阅命令及前端/后端确认校验同步移除旧建议回退；保留真实规范批次的版本、来源、适用性和未决项校验。历史已采纳值、审阅历史和需求基线不作数据清洗。
5. 验证无批次、自引旧建议、合法规范批次、失效批次、手工填写与澄清场景。使用受影响文件级测试和浏览器检查，不执行无筛选全量。

## 验收

- 初次进入截图案例，6 条需求不再显示伪规范证据或“增强建议尚未处理”；需求原文引用仍可定位。
- 显式生成规范建议后才显示对应证据及采纳/不采纳操作，按需求 ID 对齐。
- 接口不能绕过页面采纳旧识别建议；未处理的真实规范建议仍阻止确认。
- 页面刷新无需重分析或删除既有项目数据；原研制任务书装配与生成逻辑不改。
