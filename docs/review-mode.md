# 研制任务书审阅与修订

生成结果和历史任务中的“进入审阅”打开 `/review/{任务ID}`。已生成但交付门禁阻断的文件也可审阅。主页业务导航不增加新的管理模块。

## 内容对照与正文编辑

页面将本次需求、实际使用模板、产品规范与任务书并排显示。章节目录与来源联动使用当前文件的内容标识；无法确认唯一对应关系时显示待核对。内容视图展示段落、表格与图片，不模拟 Word 原始分页。可下载归档原件核对版式。

点击“编辑正文”可修改普通段落及表格单元格内文字、添加或删除允许编辑的段落。保存只修改 DOCX 的正文 XML，媒体、样式、多级编号、页眉页脚等其他部件保持不变。域、公式、超链接及特殊结构交由版式编辑器处理，避免破坏原有结构。

原始生成件永久作为基线保留，界面明确显示其归档时间。保存产生新修订版，恢复历史版本也产生一个新版本。未保存的修改保留在当前页面，并在离开前提示；保存冲突不会覆盖较新的版本。

“重新检查”针对所选已保存修订版读取归档规则和生成证据，不调用生成模型，不改写正文。结果区分基础检查通过、需人工核对、检查不通过、检查执行失败。人工修改会重新核对来源、指标与适用规则；基础检查通过不自动等同于交付批准。标记已核对只属于对应修订版，不覆盖原始生成报告。

## 文件存放

审阅资料位于配置输出目录下的 `reviews/{任务ID}/`，与输出数据卷一起持久化。包括原始生成件、修订件、需求/规范/模板副本、规则快照与独立检查记录。上传临时目录清理不再影响已经归档的审阅任务。

新任务在生成时记录实际使用模板及规则。旧任务首次打开时仅收集仍存在的本任务材料；缺失文件或规则明确提示，不以当前模板和规则补充历史事实。

## 可选版式编辑服务

完整的 Word 式版式编辑使用内网 ONLYOFFICE Docs；无此服务时正文编辑仍可用。服务需要独立镜像及数据卷，平台主镜像不包含文档编辑器。

设置私有 `.env` 的 `JTB_REVIEW_EDITOR_SECRET` 为至少 32 字符的随机值，然后运行：

```sh
docker compose -f docker-compose.yml -f docker-compose.review.yml up -d
```

浏览器默认通过 `http://127.0.0.1:18160` 访问编辑器。远程部署时，`JTB_REVIEW_EDITOR_URL` 必须改为用户浏览器可访问的内网服务地址；平台与编辑器内部通信由 Compose 服务名完成。HTTPS 平台需配套 HTTPS 编辑器地址。

开发环境中的三个地址分别为：

| 环境变量 | 用途 |
| --- | --- |
| `JTB_REVIEW_EDITOR_URL` | 浏览器加载编辑器脚本和界面 |
| `JTB_REVIEW_EDITOR_INTERNAL_URL` | 后端访问编辑服务和接收编辑文件 |
| `JTB_REVIEW_PUBLIC_URL` | 编辑服务读取平台文档及回调平台；Docker 中不能用主机的 localhost |
| `JTB_REVIEW_EDITOR_SECRET` | 平台与编辑服务共同使用的 JWT 密钥，不返回浏览器 |

编辑回调必须通过签名验证。后端只读取配置的编辑服务返回的文件，且保存仍检查期望修订版；旧窗口无法覆盖后来保存的版本。点击平台的“保存版式修改”后，只有平台收到 DOCX 并写入修订存储才显示保存成功。编辑器内部保存仅同步到文档服务。

离线部署需另外准备对应文档编辑服务镜像、配置与字体，并核对所用发行版的嵌入使用条件。复杂模板上线前应核对合并单元格、多级编号、公式、图片与页眉页脚。

集成依据：[部署](https://api.onlyoffice.com/docs/docs-api/get-started/installation/self-hosted/)、[保存回调](https://api.onlyoffice.com/docs/docs-api/usage-api/callback-handler/)。
