## 修复内容

1. 兼容接口传递 `response_format=json_object`，此前 `json_mode` 在适配层丢失。
2. JSON 解析前检查 `finish_reason`、空响应和拒绝响应；截断时不接受 JSON 碎片。
3. 达到输出上限时，在配置上限内最多恢复一次。本机为 4096→8192；到达配置上限后仍失败则明确报错，不无限重试或静默换模型。
4. 日志记录模型、结束原因、请求额度、输出/推理 token 用量及正文长度，不记录认证头、提示词或模型正文。
5. 即使网关漏报 `length`，解析器也不再从不完整外层 JSON 中提取内层对象作为完整结果。
6. 分类失败提示保留具体原因，取消一概要求“配置可用 LLM”的误导文案。
7. 前端统一 SSE 和轮询终态处理，正确显示失败、取消和阻断；错误去重，失败后刷新历史。
8. 后端错误、异常和取消任务均持久化，重启后恢复状态和错误；无成品时不显示下载入口。

原失败任务基于实际 API 快照保存为 `basic-service/app/正式输出/26c4677f0f.job.json`。记录保留失败事实，无生成文档、报告或伪造成功结果。
