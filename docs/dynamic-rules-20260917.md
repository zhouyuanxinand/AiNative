# 动态规则中心

规则中心已从只读摘要升级为业务字段编辑器。使用当前运行平台顶部的“规则中心”进入。

## 使用方式

1. 在左侧按分组或搜索选择规则。
2. 在表单中修改业务文本、识别词、领域选项、阈值或已有开关。
3. 点击“检查修改”查看校验结果和修改前后的值。
4. 可填写修改说明，点击“保存并生效”。新建任务直接读取保存后的规则，无需重启服务。
5. 展开“修改记录与恢复”可查看修改人、时间、说明，并恢复历史内容。恢复会追加审计记录。

规则以版本号检查并发修改；其他用户先保存后，旧页面不能直接覆盖新版本，需要重新读取。未保存的内容在切换规则或离开页面前会提醒。

有生成中或排队任务时可以编辑、检查修改，但保存和恢复需等任务结束。这样可以确保正在生成的任务从分类到交付检查始终使用同一套规则。页面提供“刷新运行状态”，不会清空编辑内容。

## 覆盖范围

| 分组 | 可维护内容 |
| --- | --- |
| 6 组语义分类 | 低频、射频、滤波、线缆组件、液冷管路、液冷机箱与冷板的分类定义、识别词、目标语义标题及原文拆分参数 |
| 17 类产品指标规则 | 当前已启用产品的指标名称、精确识别词、有效来源及产品专属交付/质量规则 |
| 研制流程与六性证据 | 已支持流程的别名、相关章节及证据词 |
| 标准与领域适用范围 | 标准族、模板条件标记、领域章节及适用范围 |
| 历史故障说明 | 本产品和系列无匹配故障记录时的业务说明 |
| 文档质量检查 | 实际生效的格式阈值、模板残留词、结构检查与提示开关 |
| 模板分支 | 研制经费不同模板分支的标题识别条件 |
| 指标词表 | 共享指标规范名称和精确别名；是否引用由各产品规则控制 |

共 31 份实际生效的规则文件。模板文件路径、稳定标识、未实现动作和只用于旧展示的配置不作为可编辑业务字段。新增产品、领域或新的执行动作仍需接入相应代码与模板。

原始 `研制任务书生成规则7-22.xlsx` 是规则依据，平台不直接解释该 Excel 执行。本次编辑中心管理运行时 YAML 业务参数；Excel 指标词表和故障数据库的记录维护不在此页面。

技术数值仍来自本次输入材料；原文覆盖、来源追溯及实际图文完整性检查由生成流程执行。保存质量检查参数不会更改已有任务或生成文档。

## 实现与验证

- 后端 `rule_editor.py` 维护资产/字段白名单、类型与引用校验、指标同义词约束、版本冲突及原子写入。
- `taskbook_controller.py` 暴露目录、详情、修改校验、保存、历史和恢复 API；发布后立即清除规则读取缓存。
- 新任务记录 `rule_revisions`，为当次使用的各项规则保存版本标识。
- `qa_policy.py` 统一 fill 和流水线的质量规则来源，避免前段仍使用固定规则而使编辑失效。
- `test_rule_editor.py` 覆盖字段约束、无效配置、版本记录、恢复与写入失败；测试只使用临时规则副本。
- `test_rule_editor_api.py` 通过真实 HTTP 接口验证保存、缓存失效、运行任务互斥及恢复。
- `test_dynamic_qa_policy.py` 用实际 DOCX 验证阈值 0→1→0 对质量检查结论产生对应变化。
- `web/tests/rules-editor.browser.mjs` 验证编辑、差异、保存、并发冲突、恢复、未保存提醒及手机布局。

验收结果：规则存储 34 项测试、API/质量检查及相关回归 60 项测试与 4 个子测试通过；新增后端代码静态检查通过。运行中的真实服务已返回 31 份规则、2017 个有效字段，HTTP 修改校验成功且当前规则与历史记录未被改变。

规则历史写在服务配置的模板发布目录下的 `rule_history/`，与业务源码分开保存。认证信息及模型凭据不进入规则目录和修改记录。
