## 评审后修正

1. 原资源整体停用跨版本共享，却只对单版发布修订做CAS：增加独立`control_revision`，状态命令必须同时提交head、固定版状态和整体状态修订。确定性交错及双线程测试均覆盖，旧请求不能恢复刚停用的资源。
2. 界面原“停用版本”与保留的整体停用语义不一致：改成“停用资源”，明确所有版本暂停；旧版已发布但整体停用时允许显式“恢复发布”，授权按钮禁用。
3. 冲突详情刷新和变更请求的迟到200可能发生在并行403清屏之后：增加与列表读取相同的权限代次检查，禁止旧响应回填配置或覆盖撤权提示。
4. 路由入口原只保留主页面参数，丢失新的目录参数：精确扩展`flow_*`与`workspace_*`已知参数白名单，不开放任意查询键。

上述调整属于本批接口和状态一致性，已同步计划/设计约定。独立审查报告为`2026-11-01-phase2a-review.md`，确定问题均关闭。

## 本地使用与部署配置

当前平台已重启在 `http://127.0.0.1:18370`（后端18372），统一登录关闭，保留原本地负责人确认设置。当前Workspace默认只读，不自动给本地访客或研发管理员资源治理权。

| 配置 | 含义 |
|---|---|
| `JTB_RD_WORKSPACE_APP_ID` | 能力应用标识，默认`rd-platform-local`，不是OA App ID；其他应用无内置默认授权 |
| `JTB_RD_WORKSPACE_PUBLISHERS` | 逗号分隔的已验证主体ID，可编辑/发布/停用资源 |
| `JTB_RD_WORKSPACE_GRANT_MANAGERS` | 逗号分隔的已验证主体ID，可授予/撤销当前应用的固定资源版 |
| `JTB_RD_LOCAL_WORKSPACE_ADMIN=1` | 仅OA关闭且请求来源回环时的显式开发开关，两种测试权均开启；当前运行实例未开启 |

部署人员可由`/api/rd/session`核对已验证主体ID，再分别配置角色；不使用浏览器展示名、客户端传入角色或OA管理员名单推导。正式企业角色同步和外部Workspace接口在P4对接。当前页面授予默认无截止时间，服务端可接受UTC截止时间；界面不伪装完整企业投放审批制度。

没有迁移工程项目数据，没有改原文档引擎，没有远程推送。本批代码及计划保留在当前工作树，待用户安排提交。P2B完整流程设计器及P3本体补缺另批实施。
