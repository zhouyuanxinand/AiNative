# 需求确认：逐项对照规范生成建议

## 目标和范围
- 在需求确认表增加“按规范生成建议”，使用当前流程的编制模型，对已采用需求清单逐项检索当前主产品规范。
- 规范原文、证据定位、AI 建议、用户实际结果分开保存。规范缺项显示未找到；条件或阈值冲突提示澄清，不把历史产品能力当成客户要求。
- 本体 Agent、K-box、客户画像、产品画像仅留下证据提供方扩展注释，本次不接入、不伪造检索结果。

## 实施
1. 独立建议模块：按需求 ID 分批核对规范，校验引用确实来自当前主规范、条款完整和匹配对象；覆盖全部需求。安全补充沿用原有严格建议校验，差异保持原指标。
2. 独立建议批次：固定需求版本、来源哈希、模型和时间；慢调用不持有数据库事务。沿用项目权限、版本并发控制和幂等回执。失败保留已有结果。
3. 逐项采纳、不采纳、填写实际结果继续使用已有版本链。需求或来源变化使相关建议失效；处理一行不会让其余行失效。建议不自动审批或改写需求。
4. 证据接入现有文档定位和全文预览，保存 DOC 转换副本以支持定位回溯。
5. 界面沿用现有 Ant Design 表格：一个生成/重新核对入口、处理状态、规范摘录和简短建议；已有草稿须先处理。没有规范时明确提示补充主规范。

## 验证
- 定向模块测试：匹配、不同阈值/工况、未找到、无效引用、遗漏/重复 ID、模型失败、分批覆盖。
- 定向存储与审阅测试：权限、并发、回执、失败保留、单行处理、来源变更、当前批次采纳和旧批次拒绝。
- 相关证据定位、原有建议和需求确认测试；前端构建；可用时浏览器检查。
- 用独立测试项目和已提供的两份液冷 DOC 做真实模型核对，不覆盖用户当前项目，不改旧任务书生成引擎。
- 本轮不运行无筛选全量测试，不自动提交代码。
