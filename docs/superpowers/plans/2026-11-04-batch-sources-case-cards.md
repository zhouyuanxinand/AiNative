# 批量资料整理与项目流程卡片

用户要求及本轮确认：封面阶段、产品归属范围前置到新建项目的折叠选项，默认 F / 非中央研究院产品；系列从需求文件名或封面识别，缺失可在后续确认；批量拖入文档、自动分类并拖动调整；业务流程卡片补齐真实数据和操作。同类多文档每类一份主文件，其余为补充资料，保持原生成引擎。

## 设计与范围

沿用既有 Ant Design、矿物蓝、免费字体和自然页面滚动。新建项目默认折叠“更多编制选项”，展示简短默认摘要；仅新建时提交默认值，历史项目不改写。后续案例继承项目这四项预置分类。资料识别页删除阶段/归属的重复卡片，只保留研制流程、产品系列及必要冲突。需求确认工作面支持缺失时明确确认，修改走原 save_context 与失效机制。

上传区采用一个拖放入口和待上传分组，不增加新的页面。用户可一次选择或拖入多份文件；先按文件名给出类别建议，存在歧义留待分类，可用当前模型进一步识别文件名。模型只给建议，不触发上传或覆盖人工调整。用户可拖到“需求文件/产品规范/补充资料”分组，也可用下拉完成同样操作。需求/规范各至多一份主文件，明确展示主文件标记；已有主文件默认保持，新替换涉及已采用资料时沿用确认。

批次提交携带每份文件的类别和主文件标记、版本与幂等键。后端单事务保存并一次性更新选择，整批失败可重试同一请求，未知结果锁住队列避免重复创建。非主文件保存为 reference，同时保留 document_category 供展示其分类，全部文件可追溯；原引擎仍只有一份 tech 与一份 spec 正式输入。文件内容不是系统指令，文件名分类不解析可执行指令。上传限制和授权保持现有规则。

产品系列仅从需求来源提取，封面明确“产品系列/型号”优先，文件名提供可追溯候选；泛化名称不猜值。多个不同候选展示冲突供确认。文件名证据与正文分开，不可用文件名伪造工程需求引用。缺失时在需求确认补充，编制准备可返回该入口。

流程卡片以现有固定图及 node_states、当前输入工作包和交付记录投影，展示当前步骤、已完成节点/总数、待办或受阻、项目负责人、工作包计划截止、当前成果及交付状态。无记录使用“未设置/未记录”，不填演示百分比与日期。主操作为继续办理/查看成果；辅助查看流程与成果依据，均接入真实导航，不新增删除流程或审批能力。

## 实施顺序

1. 独立后端模块/接口：批量文件名分类、原子批量上传、系列候选证据与四参数继承；针对现有失败/幂等/输入选择测试。
2. 独立批量上传组件：多文件队列、拖入/分组移动、主文件选择、手工分类、统一上传与失败保留；接原 dirty/busy/替换确认。
3. 根页面：新建折叠参数、API/runner对接、系列确认入口、资料布局精简。
4. 独立项目卡片与数据投影、真实操作接入。
5. 检查实际浏览器桌面与窄屏、拖放与键盘替代、失败重试与导航；只运行受影响文件、类型检查与构建，复用已通过结果。测试使用隔离资料和API，不修改用户项目或调用真实模型；本轮不提交Git。

## 验收

- 新建默认折叠且提交正确ID；旧项目不补默认。
- 一批多文档分类可改、每类主文件明确，补充文件不会覆盖主文件或丢失，重试不重复。
- 系列文件名/封面识别有证据，未识别有确认入口；原工程需求引用和任务书引擎不退化。
- 卡片数据真实、有无数据均布局完整，导航可达，窄屏无横向溢出。
- 保存仍遵守版本/权限/来源失效；批次和模型失败不伪装成功。
