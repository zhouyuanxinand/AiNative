# 故障数据库

顶栏“故障数据库”用于维护产品发生过的故障和改进经验。首次运行自动接入现有受控故障库，原 Excel 保留，后续维护内容持久保存到 SQLite。

## 日常操作

- 查询：按产品类型、系列或型号筛选，也可搜索产品名称、失效部位、故障现象、原因和改进经验；结果分页显示。
- 查看：点击“查看”，阅读完整故障现象、原因及措施。历史导入记录可展开“原始导入信息”，查看原文件、工作表、行号和全部原字段。
- 新增：点击“新增故障”，选择产品类型，填写数据所属产品、系列或型号、失效部位、故障现象、原因、改进措施与经验，保存即可。
- 修改：点击“编辑”或详情中的“编辑记录”。多人修改同一条记录时，过期版本会被拒绝，重新打开最新记录后再修改。
- 删除：点击“删除”，核对产品和系列后确认；记录从列表和后续生成匹配中移除，已生成的文档不改写。

故障原因或改进措施尚未明确时可留空，系统不会代写缺失的业务事实。

## 与任务书生成的关系

页面和生成程序读取同一份数据库。后续生成按现有研制流程规则查询历史故障，并把匹配的故障现象、原因、改进措施与经验填入相似失效问题规避表。

填写明确的产品系列后，记录按该系列匹配；系列未确认时留空，继续按照原始所属型号匹配。导入时不推断系列归属，不把 J599/20、J599/21 自动归为 J599L。没有匹配记录时沿用现有“未查询到历史故障信息”规则。

一次匹配读取一致的数据快照，生成审计包含数据库版本、内容指纹、记录编号和记录版本。删除的记录保留操作留痕，但不再用于匹配。

## 数据存放

默认文件为 `basic-service/app/runtime/failure_database.sqlite3`；可用环境变量 `JTB_FAILURE_DATABASE_PATH` 指定存放位置。该文件应纳入平台业务数据备份。备份正在使用的数据库时使用 SQLite backup 接口，或停止服务后复制文件。

旧库 `src/service/jonhon_taskbook/resources/mappings/failure_mode_database_20260722.xlsx` 仅用于首次导入；服务重启不会重复导入或复活已删除记录。

当前导入 2,357 条有效记录，跳过 1,000 行空记录。全部原始非空字段均保留；其中 709 条属于当前产品目录以外的历史分类，可通过“其他历史产品”或关键词查询。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/failures` | 关键词、产品、系列/型号筛选及分页 |
| `GET /api/failures/options` | 产品选项及记录数量 |
| `GET /api/failures/{id}` | 详情及原始导入信息 |
| `POST /api/failures` | 新增 |
| `PUT /api/failures/{id}` | 修改，携带 `expected_version` |
| `DELETE /api/failures/{id}?expected_version=...` | 删除指定版本 |
