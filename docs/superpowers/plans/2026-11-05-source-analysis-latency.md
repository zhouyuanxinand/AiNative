# 资料分析等待与晚到结果提示修复计划

## 已复现证据

同一次真实请求关联日志显示：总耗时 341.50 秒、最终 HTTP 200。第一次模型请求先后等待 91.23 秒、90.21 秒超时，第三次 72.89 秒成功；随后另一轮 JSON 模型调用 70.80 秒。模型等待共 325.13 秒，占总时间约 95%。前端分析请求 300 秒超时，因此先显示失败，服务端稍后仍保存了结果。读取最新版本可见新结果，但组件的失败状态未跟随新分析批次清除。

## 修改范围

1. 资料分析使用独立的 240 秒处理预算；单次模型尝试最多 120 秒、最多 2 次，首次分析、输出截断恢复、纠错共享剩余预算。默认任务书生成和其他模型请求保持原策略。预算结束明确返回超时，失败不覆盖旧提案。
2. 保留全文读取、全部需求和原文真实性校验。纠错优先只返回错误项目的修订，服务端合并后仍运行原有完整校验和不允许删改正确行的检查，减少重新输出整份结果的等待。
3. 增加资料提取、初次模型、校验纠错的阶段耗时日志，不记录凭证或正文，便于之后确认真实耗时。
4. 前端记录失败请求所基于的分析批次。读取到本次开始之后的新且有效分析结果时清除失败提示；仍是旧分析时保留。不得因页面上有任意数据就认定请求成功。

## 验证

- 用可控时钟和真实模型客户端重试边界复现预算问题，先失败后修复；覆盖首次请求、重试、截断恢复及跨调用共享预算，原调用方默认行为保持。
- 用原文错误项目测试部分纠错并保留全部原有校验断言；只跑完整受影响测试文件，不执行无筛选全量。
- 浏览器隔离数据验证超时后旧结果提示保留、新结果恢复提示消失、原输入草稿保留。
- 如本地凭证和服务可用，以真实来源只读快照执行一次验证并记录实际耗时，不审批、不采用、不改用户项目。
- 不提交代码；完成后检查本地服务与页面可用性。
