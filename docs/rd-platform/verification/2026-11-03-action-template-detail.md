# 动作模板完整画布验收

## 交互与数据范围

动作模板目录卡片点击后进入完整画布，不再在卡片内展开配置表单与缩略图。返回目录保留搜索词、页码、所选资源和固定版本；地址包含 `flow_item`、`flow_version`、`flow_detail=canvas`，直接打开仍按固定版本读取。

画布展示服务端保存的 `execution_graph`，不增造节点，也不修改执行配置。仅对展示名称补齐：优先使用节点已保存名称，其次查成员的固定资源版本名称，最后使用同一固定版本的注册动作名称。名称仍缺失时显示通用步骤名并提供重试，不取其他版本代替。空角色字幕使用“执行步骤”，不推断专家分工。

节点数量以读取到的执行图为准。单节点显示“单动作封装”，多节点显示“多步骤编排”；目录在尚未读取详情时不猜测节点数量。固定成员与输入输出作为按需展开的附属资料，不占用主画布。

## 验证

`web/tests/rd-action-template-detail.browser.mjs` 在实际组件与隔离 API 数据上验证：

1. 目录卡片没有内嵌画布；进入固定版本完整画布；模拟 503 后可重试；单节点保持单节点；返回保留查询、页码和选择。
2. 三节点编排优先保留已有名称；成员固定版本名称优先于目录注册名；无权直接读取依赖成员时只回退至同版本的注册名称；桌面与 390px 窄屏自动适应画布，不产生页面横向溢出。
3. 固定版本详情直达地址遇到 403 时显示可重试错误，不遗留旧画布，不替换成最新版本。
4. 输入搜索词后，在 300ms 搜索防抖提交前点击卡片，原子保存新搜索词与所选固定版本；等待防抖时间后详情仍在，返回目录显示新词且页码重置为 1。未改关键词时原页码继续保留。
5. 未绑定执行能力、仅有成员的合法模板，其目录投影中可选输入、输出、执行图为 null 时，展示空图说明与真实成员；非空但结构非法的执行图继续显示错误，不吞掉异常。

结果：5 组通过，页面运行错误 0，真实业务写请求 0。TypeScript `tsc --noEmit` 通过。追加两项均先通过浏览器用例复现失败，再修复验证。
