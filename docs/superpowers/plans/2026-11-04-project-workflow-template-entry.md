# 项目从流程模板启动，任务书生成终止流程

**目标：** 用户仅使用“流程模板”概念，新建项目从流程管理的已发布项目流程中选择。新增“研制任务书生成流程”，终点为研制任务书生成。

**用户明确决定：** 不新增业务场景目录；统一使用流程模板；新模板到研制任务书生成即止。

**设计与边界：** 复用现有 WorkflowTemplates 的版本、校验、发布、停用、历史和画布治理。新增内部用途 `project`，界面称“项目流程”；保留已有选型/研发阶段模板。初始固定图为资料受理 → 需求确认 → 成熟产品比对 → 选型决定 → 研发启动依据 → 研制任务书生成。最后节点绑定已有完整任务书专家团，原受控模板、来源搬运、补缺、原引擎与质量校验继续执行。无方案设计、详细设计、整合、交付等后续节点。修改位置/名称不修改代码，不能绕过已有业务依据及质量门禁。

创建项目流程时以服务端发布版 id/version/digest 固定模板和图，已有项目保留采用版本；草稿、停用版、未授权能力不可被新建采用。后续任务书输入采用引用已选固定流程，避免再选择一套包含后续研发节点的流程。旧案例保留原办理方式与历史数据，内部兼容字段不作为新用户概念呈现。

流程完成仅依据当前输入对应的真实执行与门禁结果；存在复核文件/受阻记录不等于完成。不自动授予正式审签或生成内容依据。旧项目不自动迁移、改名或覆盖。

**技术：** 既有 React/TypeScript/Ant Design、StyledSelect、FeedbackDialog、离开保护；Python/SQLite 流程治理与工作包执行。复用既有主题、滚动与画布组件，不新增 UI 库。
