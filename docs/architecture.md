# 代码结构与模块职责

本仓库采用一个前端应用、两个 HTTP 进程和共享业务模块。目录按维护职责组织，保留现有部署路径和业务行为。没有把四个平台拆成四个空服务，也没有引入新的框架。

## 前端

`web/src` 分成三层：

| 目录 | 职责 | 新功能放置原则 |
| --- | --- | --- |
| `app/` | 路由选择、应用壳、跨功能装配 | 页面入口和平台导航放这里 |
| `features/rd/` | 项目、需求、任务、成果、审签与项目流程 | API、模型/纯函数和 UI 随业务归属放在同一功能目录 |
| `features/taskbook/` | 任务书工作台、原生成器、版本审阅 | 原生工作台与独立工具共享已有生成能力 |
| `features/assistant/` | 小航对话、操作预览、人物动画与拖动 | 不直接绕过后端执行业务写入 |
| `features/admin/` | 管理员工具、日志、规则等 | 保留管理员访问契约 |
| `features/feedback/`、`help/`、`settings/` | 用户反馈、操作资料和设置 | 按现有功能集中维护 |
| `shared/` | HTTP、身份、通用 UI、通用 hooks/工具 | 只放被不同功能复用且不含特定业务语义的代码 |

依赖方向是 `app → features → shared`。功能间确实需要调用时使用对方的 API、模型或明确入口，不从页面组件中取共享函数。类型依赖使用 `import type`。不要把所有东西重新堆到一个 `utils.ts` 中，也不要求每个功能都有相同的空目录。

项目显示名称、上下文类型和 `RdSection` 已从 `RdWorkbench` 页面抽离，项目链接归入研发模型层，避免页面互相引用及模型依赖 UI。全局样式与功能样式保留原加载顺序，DOM、文本、组件挂载关系不因本次迁移改变。

## 后端

运行根目录仍是 `basic-service/app`：

| 目录/入口 | 职责 |
| --- | --- |
| `src/main.py` | 主服务启动，兼容 `python -m src.main` 与 `uvicorn src.main:app` |
| `src/application/` | 路径与启动引导、应用工厂、中间件、静态页面和生命周期 |
| `src/feedback_main.py` | 独立管理员应用；使用共享 HTTP 能力，不通过导入主应用来复用中间件 |
| `src/controller/` | HTTP 请求校验、身份依赖、响应映射和各功能路由 |
| `src/controller/rd_dependencies.py` | 研发 HTTP 的身份、幂等键、请求基类和错误转换 |
| `src/service/rd_platform/` | 项目聚合、基线、流程、任务书工作流、审签、交付和持久化 |
| `src/service/rd_platform/runtime.py` | 配置驱动的项目 store 构造与缓存，供装配和适配层使用 |
| `src/service/assistant/` | 小航意图识别、问答、注册操作及确认执行 |
| `src/service/jonhon_taskbook/` | 受控生成内核、规范化、语义路由、文档装配和 QA |
| `src/service/config/`、`prompts/` | 受控规则和提示词 |
| `src/common/`、`utils/` | 身份、日志、请求归档、配置读取等已有基础能力 |

HTTP 控制器调用业务模块，业务运行配置不从控制器获取。研发项目 `RdStore` 仍是事务入口，版本检查、权限、幂等结果、事件与项目写入继续在同一事务内完成。小航仅调用注册操作，经预览和确认进入原有业务规则。

任务书生成包和资源的物理位置保持不变，避免资源寻址与固定输入包指纹改变。原生成控制器和项目事务核心规模较大，仍按现有接口维护；未来若拆分，应单独验证状态生命周期和事务原子性，不为目录对称而增加中转层。

## 四平台的后续接入

研发管理负责业务流程与工程决策。K-box、本体、Workspace 分别承接知识治理、工程事实与规则、资源生命周期。现阶段本地已有实现保留，后续 API 接入应在已经拥有相关职责的模块内替换适配，不让页面直接依赖外部平台或改变任务书受控生成契约。

## 测试与仓库内容

- 后端 `app/tests/{rd_platform,assistant,platform,taskbook}` 按业务范围组织，包含纯函数、SQLite、API 和文档回归，不统称单元测试。
- `app/tests/support` 存公共场景工厂和路径，测试之间不互相导入测试函数；`fixtures` 存受控样例。
- 前端 `web/tests/unit` 验证模型、导航与 API 行为；`browser` 验证浏览器行为；`live` 明确依赖真实服务。
- 根 `tests/e2e` 启动隔离数据库与实际 HTTP 服务，检查跨前后端行为；`tests/live` 是手动真实模型探测。
- `scripts/check.py` 固定工作目录和运行器，默认只运行离线前后端检查。浏览器、端到端、真实联调必须指定用例。

源码、测试、锁文件、配置模板、受控文档模板、必要脚本和开发文档都属于可复现项目。`.gitignore` 排除真实凭证、运行数据、依赖目录、编译结果、浏览器证据和本地助手过程文件，不按语言扩展名或整个测试目录粗暴屏蔽。
