# 规范建议操作与原始指标采纳

用户最终确认：已找到规范依据只提供办理澄清，自动填入规范建议指标，最后统一确认需求；适用性待核对提供采纳、不采纳、办理澄清，采纳原始指标。

## 开发范围

1. 表格根据建议状态显示操作。上述两种状态移除编辑需求；已找到规范依据同时移除采纳/不采纳。其他状态保留已有行内修订。
2. 后端从当前已采用的资料分析读取本行原始指标，适用性待核对的采纳不使用模型建议值，记录明确的原始指标采纳来源。没有有效原始指标时转入澄清，不猜测内容。
3. 保留批次、需求版本、输入版本、当前来源及权限校验。适用性待核对采纳前实际结果为 --；明确采纳后才赋值。不采纳保持待澄清，由用户主动打开办理，不自动跳转。
4. 已找到规范依据的当前有效建议自动成为待统一确认的实际指标，不伪造用户采纳记录。前后端确认门禁与最终需求基线同步；明确采用的澄清优先，过期建议不能作为有效结果。
5. 前端实际结果及确认门禁同步识别原始指标采纳凭据；过期或伪造记录不能作为有效结果。
6. 复现并修复表格采纳、不采纳后的页面跳顶，保持操作行和滚动位置；澄清打开与返回也不丢失位置。

## 验证

先添加并运行定点回归，覆盖匹配建议自动赋值与统一确认、原值和建议值不同、缺失原值、未采纳、拒绝后采纳、过期版本及伪造值；随后运行完整受影响测试文件。浏览器验证分状态操作、原值采纳、其他状态行内编辑、只读和操作滚动保持，完成前端构建。不执行全量测试，不操作真实项目。
