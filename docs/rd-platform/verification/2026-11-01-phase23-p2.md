# P2 设计领域、编译执行及 P3 checkpoint 集成

日期：2026-11-01。工作树：`codex/rd-platform-rebuild-20261031`。保留已有 P2A 修改；未提交、未推送、未重启用户服务。本文是 T1 的领域与本地测试回执，真实服务/浏览器/原引擎样本联调由总验收记录另行列明。

## 实现结果

- `rd_platform/designer.py` 提供同一种结构化 patch：增删/复制节点、增删边、属性、位置和人工确认字段。项目 CAS、草稿 revision 和 base digest 同时检查；人工确认字段的助手/对话覆盖形成冲突。保存与位置修改不提交 Run，也不形成工程决定。
- 草稿、修订历史、不可变执行候选、采用事实、模拟回执分开保存于现有项目事务。准备锁定输入/规则/资源摘要，采用和提交重新检查；新业务政策创建的工作包从一开始就是 schema 3，客户端不能声明旧 schema 绕过采用。历史 `legacy_v1` 服务端对象保持原执行语义。
- 从历史恢复创建新的干净工作包和草稿，保留 `revision_of`/`source_run_id`，不复制 Run、结果、制品、采用或执行时间。当前案例的阶段和业务批准不被恢复操作改变；旧 Run 只读。跨阶段修订仍受提交阶段门禁约束。
- 新默认动作是 Workspace 固定专家团：任务书编制、一致性、上下文解析、成果校验。任务书专家团实际展开为原来的 `resolve_context → template_plan → content_completion → generate → verify`。没有第二个调度器，也没有替换文档生成器。原 `engine_bridge → pipeline_cli` 入口未改动。
- 专家团内部图只接受固定六个已注册 Skill 执行器；成员、内部 DAG、输入输出合同及应用许可核验。未绑定 Agent、任意表达式、循环、显式并行结构和嵌套团执行被准确阻断。独立 DAG 节点仍由既有 Worker 串行执行。
- 同名动作实例的结果按节点保留在 `__by_node__`，旧执行器所需角色键由当前消费者的明确生产者绑定产生。内部绑定先从固定团队图导出，再合并实例；复制整团后仍各自读取本团模板计划及补缺结果。schema 3 允许重复已注册动作，但每个必需动作实例都必须保留前置检查及可解析输入；旧计划规则不放宽。
- Run 快照保存采用候选摘要、原业务图、图/布局摘要、资源锁，以及 `business_node_id → action_instance_id → step_instance_id → run_id` 映射。后续修改草稿不会改 Run 快照。
- `workflow_templates.py` 持有选型/研发两类业务模板的不可变内容版、发布状态修订、独立权限、CAS、幂等和审计。模板编辑/发布权限与 Workspace 发布及应用投放权限分离。项目采用只固定模板，不创建研发工作包，也不代替选型、启动、范围或工程审签。状态从既有业务事实投影。
- 已采用业务图的固定 `action_resource` 会实际创建动作实例：研发任务书节点必须绑定完整任务书合同，策划范围的新增获准动作会一并编译；依赖跨越纯业务节点时保留其先后关系。发布和项目准备使用同一个 `Designer.compile`。正例已验证团队 V2 内含新增一致性步骤，外加一个业务检查节点，Worker 按固定图实际执行 7 步；映射保留 `taskbook`/新增业务节点身份。不能执行的后续业务阶段或作用域在发布时阻断，不能只存引用后忽略。
- 独立采用研发模板会使不一致的旧任务书绑定过期；显式采用任务书流程则在同一事务中固定相同的研发模板采用记录，避免业务图与文档绑定指向两版不同流程。
- 后续校验采用 `upstream:<step_id>` 明确绑定已完成任务书的结果，候选同时固定上游 Run 与结果摘要；重复生产者不得取任意最后一条。schema 3 校验工作包已通过真实 `executors.execute → engine_bridge.verify → QAGate` 的有效 DOCX/Profile/覆盖账本/哈希回执夹具验证，且不涉及模型生成成功声明。
- 业务节点状态仅来自当前输入、当前固定模板、匹配候选 ID/摘要及真实映射步骤；同名历史包、旧输入、旧模板和不匹配候选不能使当前节点显示完成。新增动作也投影其实际状态，新的受托 Run 会覆盖旧 Run 的当前视图；`node_execution_refs` 公开对应 Run、候选和步骤身份。决定关口只读取有效批准事实；新模板不允许把技术动作绑定成决定关口，兼容读取旧图时也始终让批准事实优先。
- 目录按获准根资源过滤后计数分页。`dependency_only` 成员可为专家团所用，但不能独立检索、查看详情或作为业务动作根；撤销任一依赖后采用、领取、续租及完成都被复核。业务模板公开详情也不泄漏失效或仅依赖授权的动作引用。
- `normal` / `missing_input` / `rejected` / `cancelled` 模拟只写隔离回执，不创建生产 Run，不调用引擎，不写正式制品或工程决定。

## 固定 API/DTO

项目命令继续使用已有 `POST /api/rd/projects/{pid}/commands`，携带 `expected_version`、`case_id`、`Idempotency-Key`：

| 命令 | 主要数据 |
|---|---|
| `create_flow_draft` | `workpackage_id`，可选 `graph` |
| `apply_flow_patch` | `draft_id, origin, base_digest, expected_draft_revision, operations` |
| `validate_flow_draft` | `draft_id` |
| `prepare_execution_bundle` | `draft_id` |
| `adopt_execution_bundle` | `candidate_id, candidate_digest` |
| `simulate_execution_bundle` | `candidate_id, scenario` |
| `restore_flow_revision` | `draft_id, revision`；返回项目含新工作包、新草稿 |
| `adopt_workflow_template` | `template_id, template_version, template_digest` |

`origin` 为 `manual|assistant|dialogue`。操作为 `add_node/remove_node/copy_node/add_edge/remove_edge/set_node/move_node/confirm_field`。节点使用独立 ID、固定资源版本、标题、角色、交付物、坐标及明确 `input_bindings`；连线为 `id/source/target`。`route` 只接受有效产品路线事实中的 `direct/modification/new`。

共享业务图的可执行节点固定 `action_resource` 和 `workpackage_definition_id`：研发当前为 `taskbook`，选型当前为 `input_check`，分别须位于任务书范围批准/选型决定关口之前。专家团内部只接受固定 Skill 图，`route`、未注册动作版本及不匹配的输入输出合同不会被静默忽略。

项目案例返回 `flow_drafts[] / execution_candidates[] / execution_adoptions[] / flow_simulations[] / workflow_template_adoptions[] / workflow_templates`。候选 `validation` 返回 `valid/errors/warnings`，错误有代码、说明及可定位节点。候选包含 `compiled_plan/resource_locks/mapping/diff`，准备后不覆写。

治理服务为 `store.workflow_templates.list/detail/save`。编辑用 `can_edit_workflows`，发布/停用用 `can_publish_workflows`，不接受 Workspace 权限替代。HTTP 接线及身份边界由 T4 完成。

## Checkpoint 合同

执行器调用 `progress({'completion_checkpoint': session})`。Store 在活跃 claim 所属事务中追加 `node.completion_checkpoints[]`，并更新只读投影 `node.completion_session`。条目附带 `run_id/node_id/attempt/fencing_id/checkpoint_digest/saved_at`，fencing 标识只返回哈希，不返回租约 token。

同一尝试相同摘要去重；同一 session 已保存轮次的前缀不可重写。取消、预算终止、撤权及来源失效保存终止 checkpoint，保留已完成轮次。迟到或失去租约的回调返回 false。重新领取内容补缺时，仅在 claim 快照附加 `completion_resume`，不修改 Run 固定快照；P3 执行器以此恢复拒绝及采纳记录。
