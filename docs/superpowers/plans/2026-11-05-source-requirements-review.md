# 资料分析：需求对照清单与全屏审阅

演示版 selection-conversation-ui.js 和 guided-project-journey.js 分开显示原始指标、建议、来源和实际结果，回复需核对采用后才能进入需求确认。保留这一业务顺序，沿用实际项目的分析、采用与澄清记录；不导入演示案例的固定五类三十项、推荐值或签审结果。

1. 在资料分析页用同一份逐项对照替换纵向预览：指标名称、原文指标与引用、公司自有组件指标、需求澄清。组件数据源未接入时不产生任何指标；提供一次可展开的本体 Agent 查询 K-box 思路，明确组件、工况、单位和受控版本。
2. 原文保持不变；通过已采用需求的稳定 ID 关联真实澄清记录，展示问题、答复、采用结果，区分未采用和历史版本。新采用时保存行到需求 ID 的映射；旧数据仅允许唯一的标题、正文及来源版本内容匹配，歧义留空。人工比对不冒充本体结果。
3. 主页面紧凑分页；“全屏审阅”打开占满视口的只读审阅表，支持检索、核对来源、关闭/Esc 并返回原页。保留既有“确认采用 → 需求确认/澄清 → 后续办理”，审阅本身不发起写操作、查询或审签。
4. 定向验证：需求采用及历史映射、资料分析页面的预览/翻页/核对/澄清/全屏打开与返回、桌面与窄屏布局；保留生成逻辑，不运行无筛选测试。
5. 需求确认页用办理表列出当前已采用需求、来源及操作。与识别页的原文对照分开：修订的是需求记录，不覆盖已经引用的原文；从两张表都可定位到有权限办理的澄清，打开记录本身不提交修改。
