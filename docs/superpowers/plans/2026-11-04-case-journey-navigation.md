# 研发案例连续办理与入口收敛 Implementation Plan

**Goal:** 将同一任务书流程收敛为可连续办理的步骤工作台，移除重复入口和标题，保留回溯、证据、审批与生成能力。

**Architecture:** 现有服务端案例、固定流程、业务决定和工作包仍是唯一业务事实。新增前端办理进度投影，统一计算步骤可用性、当前步骤与命令成功后的页面承接。导航只切换已挂载工作面，业务命令、人工确认、权限及门禁不改变。

**Tech Stack:** React/TypeScript、Ant Design、现有平台主题与本地字体。

## 设计及边界

本轮选择“步骤工作台＋成果概览”：顶部固定顺序导航承担定位与回看，每个工作面一组标题；概览只保留一个继续办理主按钮和成果证据。舍弃继续叠加快捷菜单、将所有大表单堆在同页的方案，避免重复入口和长页寻找操作。

```text
平台标题 / 项目面包屑
项目摘要（沿用已有客户、产品、目标）
资料识别 → 需求确认 → 选型与启动 → 编制准备 → 编排与生成
当前工作面标题                                      成果概览 / 助手
当前工作面内容（表单、记录、错误）
继续下一办理页面（只导航；确认与提交仍明确操作）
```

- 固定项目流程到任务书为终点；旧研发案例继续保留交付、复用、范围批准与专业设计入口。
- 步骤导航区别“当前待办”“正在查看”和“条件未满足”，不将点击步骤或保存表单伪装为业务完成。前序可回看，后序未具备条件时说明原因并禁用。
- 采用资料后进入需求核对；确认需求成功进入比对；研发启动成功进入任务书准备；固定输入成功进入工作包。失败、冲突、拒绝决定不前进；普通保存/澄清不会退回概览；执行中、失败与阻塞留在执行页面。
- 选型决定和研发启动依然是独立业务动作；下一步导航不自动确认、启动或提交工作包。
- 当前成果移除四项业务链、重复编辑CTA和“其他办理入口”；保留下载与证据查看。状态事实按实际阶段展示，未开始阶段不塞入四项空状态。
- 非资料工作面也统一一组主标题，指导语匹配正在看的工作面，去掉重复项目标题和相同版本长说明。保留失败、缺口、来源、影响和非正式审签说明。
- 页面自然滚动，桌面和390px无横向溢出；输入表单常驻，回看不丢草稿；同一助手实例保留对话。

## Ownership

- 业务事实：现有后端API、`ResearchCase`、`caseOutcomeModel`、`scenarioManifest.nextCaseAction`。
- 前端步骤/成功去向：新`caseJourney.ts`；不会建立第二套业务状态。
- 导航和工作面标题：`CaseWorkspace.tsx`与新`CaseJourneyNav.tsx`。
- 成果概览：`CaseOutcome.tsx`；局部布局消费现有AntD主题变量。
- 确认/错误/通知：既有FeedbackDialog、单一上层错误、AntD Message。
