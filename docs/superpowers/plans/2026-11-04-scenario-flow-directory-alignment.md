# 业务场景与流程管理目录对齐计划（已被用户纠正）

2026-11-04：用户明确不引入“业务场景”，统一沿用流程模板。本计划停止实施；由 `2026-11-04-project-workflow-template-entry.md` 取代。此计划仅完成调查，未修改生产代码。

**目标：** 在流程管理中找到新建项目可用的业务场景，从该目录查看办理范围并使用所选场景发起项目。

**根因：** 新建项目消费 `/api/rd/catalog.scenarios`，流程管理仅展示阶段流程模板、工作包、动作及资源，遗漏场景层级。“研制任务书生成”与后续采用的“改型研发流程”属于不同层级。

**设计：** 流程管理增加“业务场景”页签，复用同一个已授权场景目录，展示名称、发布版本、办理阶段及关联工作包，提供“使用此场景新建项目”。新建弹窗展示场景说明及返回目录的链接；目录入口预选指定场景，但仍需填写名称并点击创建。现有创建幂等、权限、资料分析、选型、模板采用及原任务书引擎保持各自现有合同。场景本轮为服务端已发布注册目录，不提供任意新增可执行场景的编辑器。

**技术与样式：** React、TypeScript、现有 Ant Design、StyledSelect、FeedbackDialog、useDirectoryState、已有矿物蓝/石墨色令牌及离开保护。业务场景优先可发现；既有 URL 页签仍可直达。目录加载/失败/空数据/关键词无结果需独立呈现，过期数据不得继续发起项目。

## 验收口径

新建项目出现的场景必须在流程管理同名可见。目录按钮打开同一个创建弹窗并选中所选场景，点击创建前不写项目。场景目录不可用时不可使用陈旧选项创建；既有项目与生成门禁不因本次界面对齐而变化。图中的阶段为办理范围说明，后续路线及具体节点仍由项目实际决定。
