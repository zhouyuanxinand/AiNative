# 流程模板画布与生命周期开发计划

> 执行：按后端治理、共用画布、流程管理工作台三个可独立验证的任务并行实施，最后联调与独立复核。

**Goal:** 让不会编程的研发人员在流程管理直接编排、校验、发布流程模板，并追溯历史版本和项目采用记录。

**Architecture:** 复用 `WorkflowTemplates` 的固定版本、发布状态与项目采用快照；将治理画布移到唯一“流程模板”入口。保留项目工作包实例编排和原任务书引擎边界，共享 `FlowGraphEditor` 的节点操作。

**Tech Stack:** React / TypeScript / CSS、FastAPI、SQLite；不新增图形依赖。

## 已明确的范围与设计

- 用户要求去掉“选型与研发流程”“模板派生与发布”两个顶级入口；保留智能体与 Skill、动作模板、流程模板、报告模板四类。
- 用户确认周期管理指模板生命周期与版本回溯，本轮不做工期、截止时间或超期通知。
- 用户要求节点拖动、取消、编辑，面向不会编程的研发人员。增加撤销/重做、复制/删除、连线、自动排列、缩放与定位，使用业务表单，技术标识收进详情。
- 当前“流程模板”只有只读 catalog 图，实际治理在独立 business 页。选择合并现有治理能力；不新建第二套模板存储，不把实例工作包图当全局业务模板。
- 画布采用现有蓝白工程风格：左侧模板目录，中间画布和工具条，右侧节点表单；窄屏依次排列。图内独立平移/缩放，不造成页面横向溢出。
- 草稿/已发布/已停用清晰呈现。编辑已发布或历史版本会保存为新修订，旧版本内容固定。校验给中文问题列表；发布重新检查，停用保留历史。
- 历史展示版本、时间、操作人、修改说明、操作事件；两版对比展示节点、连线与业务属性变化。项目引用仅展示当前主体有权读取的项目。
- 删除节点仅影响未保存草稿，可撤销；取消编辑放弃当前修改需确认。发布/停用使用共享确认弹窗。切页/切模板保留未保存保护。
- 已有任务书生成引擎和模板填写能力不改动。模板编辑不替代项目业务批准，也不自动更新项目已采用版本。
- 用户补充：编辑只能改变明确开放的配置值和条件关系，不改变具体执行代码。此轮条件为适用研发路线与节点前置依赖；节点仅引用已接入固定动作，保留必需关口。没有开放脚本、表达式、函数或执行器代码输入。

1. 编辑期间切分类/模板/顶级入口不能静默丢失草稿。
2. 旧版本查看、恢复和发布不能误用当前列表版本或覆盖项目快照。

4. 历史查询不能向模板维护者暴露其无权访问的项目。
5. 异步目录/历史/校验回包不能覆盖已切换模板或更晚的修改。
