# 流程导航与首页体验调整计划

**目标：** 从我的工作、项目空间进入任一流程后，可以连续办理、查看成果与依据，并可预期地返回；首页只呈现当前有效状态。

**方案：** 保留现有 React/Ant Design 及矿物蓝主题，修复统一入口与导航状态。路由明确当前工作面，原个人继续位置作为无明确地址时的默认。采用局部增强，不新增向导或改变业务阶段。

## 已确认的断点

- 流程内视图仅存组件状态，Back 会跳出案例，刷新辅助视图丢失位置。
- 草稿拦截 Back 通过 pushState 恢复，破坏前进历史并遗漏搜索/分页。
- 首页关注收集历史失败包，可能与项目卡统计不符；窄屏办理操作藏在横滚表格右侧。
- 当前成果/成果概览、资料与画像/成果与依据命名不同；辅助页缺少返回刚才办理步骤的入口。
- 重复进入相同成果/历史锚点不重新定位。

## 实施

1. 新增平台路由助手，解析、序列化顶级模块、项目、案例、当前视图/步骤与工作包定位；继续支持现有查询参数与深链接。RdPlatformPage统一写入历史索引，Back取消恢复同一条历史，确认继续原遍历；同案例的已挂载工作面切换保留草稿。
2. CaseWorkspace消费明确路由，合法且可用步骤优先；无明确步骤使用原继续位置。各编辑步骤更新URL；成果概览、项目流程、资料与依据页提供返回办理，统一名称。重复定位用序号触发，返回/刷新不产生业务写入。
3. PlatformHome复用项目流程当前状态投影；关注按流程去重、排除历史无效执行，问题入口打开办理面。传入统一目录可创建条件。首页保持桌面表格，窄屏使用同一数据的紧凑记录，使标题、状态与办理操作同屏。
4. 精简首页、辅助页和空成果的重复说明，保留错误、失效、权限、数据来源及业务确认必要提示。清理修改区域相互覆盖CSS，保留当前Ant Design令牌，不扩展助手修改。

## 验证范围

- 先复现导航与布局缺陷，补针对浏览器用例：内部步骤与辅助页前进后退、刷新、返回办理、跨模块草稿取消/确认、搜索分页保留、重复定位、首页关注、空/错/加载、390与1440布局。
- 路由类型/解析的针对单元测试，完整受影响浏览器文件；复用已通过的caseJourney/caseResume 40条结果，除非改到其依赖。
- TypeScript、前端构建、相关diff检查与静态UI合同审查。全部浏览器业务API使用隔离数据，不重跑模型生成、删除真实项目或无筛选全量。
- 保存截图/回执与本轮未覆盖项。用户未要求提交，保留本地改动。

## 排查补充

- 研发管理、知识管理原本仅在组件中保存搜索和分页；复用目录 URL 状态，分别保留筛选，覆盖进入案例后返回、刷新、中文输入法和越界页码。七个主模块补导航烟测，不执行业务写入。
- 知识管理右下分页被默认助手位置遮挡，分页紧邻列表计数左对齐；验证桌面与窄屏鼠标点击，不改助手。
- 动作模板详情使用的 flow_version / flow_detail 被应用入口清理；补导航参数白名单，连续刷新两次及跨模块返回核对固定版本画布。
