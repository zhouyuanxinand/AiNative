# 研发模型选择与最近使用开发计划

**需求：** 当前资料输入的编制模型下拉参照旧平台图二显示厂商和模型名称，并展示最近使用模型。保持 Ant Design 的 StyledSelect 所有权、已有填写与保存流程，不修改生成引擎。

**当前问题：** CaseInputForm 丢弃 `/api/models` 的 vendor/configured 信息；以 JSON.stringify(对象) 作选项 key，服务端字段顺序与本地构造顺序不同导致选中项无法匹配、露出原始 JSON。

**方案：**
- 复用 `web/src/lib/model.ts` 的 `modelSelectionKey`，所有模型选择与比较统一 provider/name/id 的稳定键；平台默认模型使用明确标签。
- 保留目录 vendor，按“微软 Azure · azure/gpt-5.4”等格式显示；目录加载前及历史已保存模型使用明确可读标签，未知模型厂商不捏造。
- “最近使用”在列表顶部，最多 5 个，按当前服务端会话 actor_id 和浏览器 origin 隔离，只记成功保存到项目的非默认模型，未保存/保存失败不记。刷新后保留；只缓存公开模型标识，不存凭证。
- 最近列表仅提供当前模型目录中存在且可用的模型，重复模型不在全部列表重复显示。当前历史值即使不在目录也可读，不自动改成其他模型；目录失败有原重试入口。
- 当前会话读取失败时不显示其他账号或本地模式的历史；缓存不可用时仍可正常选择和保存模型。
- 返回当前标签页时重新核对服务端身份；保存成功后再次核对会话，只有与提交前身份一致才记录最近选择，跨标签换号或身份读取失败时清除旧账号展示、不串写历史。
- 保持实际请求里的 provider/name/id，不把厂商显示名称写回调用 provider。

**文件与所有权：**
- 新建 `web/src/features/rd/modelSelection.ts`：稳定选项、厂商标签、最近模型缓存数据操作（复用 lib/model 的 key）。
- `web/src/features/rd/CaseInputForm.tsx`：目录加载、最近读取和保存成功记录、分组选项。
- `web/src/features/rd/api.ts`：同源服务端会话身份读取；遵守现有研发 API 会话和认证机制。
- `web/src/features/rd/modelSelection.test.mjs`：身份键、目录分组/去重和缓存边界定向验证。
- `web/tests/rd-model-picker.browser.mjs`：隔离 API 验证真实组件、失败不写历史、刷新及不同身份隔离、键盘和窄屏。
- `UX-CONTRACT.md`：记录本次模型选择行为。

**验收与限制：** 不跑无筛选全量；仅新增/受影响模型测试文件与类型/Vite构建。浏览器写入都是夹具，不调用真实模型、不改变实际项目模型。
