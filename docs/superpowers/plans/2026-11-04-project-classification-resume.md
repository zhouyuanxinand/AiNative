# 项目分类前置与继续办理恢复

用户要求：产品类型、质量管理体系分类移到新建项目弹窗，资料页原位置去除；从我的工作继续未完成项目时恢复办理位置，不再先落到成果概览。

## 设计与边界

- 新建项目提供两项必选下拉，选项来自现有产品目录；质量体系随产品类型联动，变更类型清除不适用值。加载和失败独立反馈，不猜默认值。
- 使用现有 create_project.context 传递受控 ID；首个案例沿用既有初始化，后续案例也继承项目的这两项分类。其余四参数、来源识别、受控模板选择、生成和质量门禁不变。
- 两项选择纳入创建脏状态、重试指纹和请求未知时的锁定。既有历史项目不批量重写。来源分析页移除两项重复参数卡及未确定提示；如资料与预置值矛盾，仍明确显示冲突原因，详细依据保留在证据页。
- 继续办理按账号、项目、案例恢复最近编辑工作面；只存页面标识，不保存表单、文件或凭证。概览、流程图、证据回看不覆盖最近编辑记录。无记录或目标不再适用时进入当前待办；运行中优先执行页，完成项目进入成果概览。
- 成果概览仍有显式入口，点击后保持概览；创建新项目直接开始资料步骤。未保存字段沿用现有离开保护，不将导航位置恢复描述为恢复未保存字段。
- 存储或身份读取失败时回退实际待办，不阻塞操作；读取账号身份后才使用个人记录，禁止串账号。老链接继续可用。

1. 新建项目弹窗接入产品目录、联动下拉及创建参数；分析页精简并保留冲突提示。
2. 后端补后续案例两项继承，定点验证初始化、来源分析不覆盖及冲突门槛。
3. 独立导航位置模块和测试；CaseWorkspace对接安全恢复与记录，继续办理/查看成果语义明确。
4. 隔离浏览器验证创建/重试、两项移除、最近步骤恢复/无记录/完成/失效回退、账号隔离与窄屏截图。
5. 只运行受影响测试文件、TypeScript与构建，复用上一轮无关通过结果；无全量、无真实模型调用或项目写入，不提交Git。
